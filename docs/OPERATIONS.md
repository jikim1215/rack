# 관리자 운영 매뉴얼 — 정보시스템 자산관리

> ⚠️ 이 문서는 **`docs/관리자매뉴얼.md`**(현재 운영환경 반영 정본)로 대체되었습니다. 최신 내용·안전 절차는 그쪽을 보세요.

> 대상: 총괄(admin) 계정 운영자 · 시스템 담당자. 설치는 `docs/DEPLOY.md`, TLS는 `docs/deploy-tls.md`, 보안 점검은 `docs/security-checklist.md` 참조.

## 1. 관리자 전용 기능 지도

| 기능 | 위치 | 비고 |
|---|---|---|
| 사용자 생성/역할/팀 배정/비활성화/비밀번호 초기화 | 설정 → 사용자 | 강등·비활성화는 다음 요청부터 즉시 반영(token_version) |
| 메뉴 권한 매트릭스 | 설정 → 메뉴 권한 | 역할이 기본, 매트릭스는 세부 제한 |
| 로그/감사 조회 | 로그/감사 | 접속기록(AC-19) + 데이터 변경 감사(append-only) |
| 정리큐 처리 | 대시보드 → 이슈 처리 화면 | 임포트 이상값 상태 관리(미조치/조치완료/무시) |
| 임포트 배치 되돌리기 | 자산관리 → 일괄등록 결과 | 삭제 예상량 분해 확인 후 실행 |
| 실사 회차 생성/마감/삭제 | 자산실사 | closed 회차는 삭제 불가(증적 보존) |
| 통계 리포트 | 통계 리포트 | 인쇄/PDF 제출용 |

## 2. 정기 점검 절차

### 2.1 일일 (약 2분)
- [ ] 대시보드 접속 — 상단 기준 시각 갱신 확인 (서비스 정상 판단)
- [ ] 생명주기 패널 주황 표시(대기 작업) 확인 → 담당 팀 통보
- [ ] 로그/감사 → 접속기록에서 `실패` 필터 — 비정상 로그인 시도 확인

### 2.2 주간 (약 10분)
- [ ] 정리큐 미조치 건수 추이 확인 (누적 증가 시 임포트 품질 점검)
- [ ] 대시보드 실장 충돌/범위초과 = 0 확인
- [ ] 백업 파일 생성 확인: `ls -lh /var/backups/asset-inventory/` (systemd timer `asset-backup.timer`)
- [ ] 디스크 여유 확인: `df -h` (data.db 크기 대비 3배 이상 여유 권장)

### 2.3 월간 (약 30분)
- [ ] **백업 복구 리허설** (§4) — 기록 양식에 결과 기재
- [ ] 사용자 계정 감사: 퇴직·전보자 비활성화, 미사용 계정 정리
- [ ] 로그 보존 프루닝 동작 확인: `journalctl -u asset-retention.service -n 20`
- [ ] 통계 리포트 인쇄 → 월간 보고 첨부

### 2.4 연간
- [ ] 자산실사 회차 생성 → 전수조사 → 마감(스냅샷 고정) → 리포트 제출
- [ ] AUTH_SECRET 교체 검토(교체 시 전 사용자 재로그인)
- [ ] 계약 만료 임박(D-60) 목록 → 갱신 품의

## 3. 장애 대응 시나리오

### 3.1 서비스 무응답
```bash
systemctl status asset-inventory        # 프로세스 상태
journalctl -u asset-inventory -n 50     # 최근 로그
systemctl restart asset-inventory       # 재기동 (SQLite 단일파일 — 별도 DB 기동 불필요)
```
재기동 후 로그인 → 대시보드 수치가 직전과 일치하는지 확인. 불일치 시 §4 복구 절차.

### 3.2 DB 손상 의심 (기동 실패, SQLITE_CORRUPT)
```bash
node scripts/deploy/db-verify.mjs data.db          # 무결성 검사 (PRAGMA integrity_check)
# 손상 확인 시 → 최신 백업으로 복구:
bash scripts/deploy/restore.sh /var/backups/asset-inventory/<최신백업>.tar.gz
```
복구 후 **감사로그 마지막 시각**을 확인해 유실 구간을 파악하고, 해당 구간의 변경(반출입/실사 등)을 수기 재입력한다.

### 3.3 로그인 전면 불가
1. `AUTH_SECRET` 변경 여부 확인 (변경 시 전 세션 무효 — 정상)
2. 특정 계정만 불가 → 로그/감사에서 `실패` 사유 확인 (잠금은 15분 후 자동 해제)
3. admin 계정 잠금 시: 서버에서 `node scripts/deploy/db-backup.mjs` 로 백업 후, SQLite로 `DELETE FROM login_attempts WHERE key LIKE 'user:admin%'`

### 3.4 실수로 대량 삭제/변경
- 임포트 배치: 자산관리 → 일괄등록 결과 → [이 배치 되돌리기]
- 개별 변경: 로그/감사에서 old_values 확인 → 수기 복구
- 최후 수단: §4 백업 복구 (유실 구간 수기 보완 전제)

## 4. 백업·복구 리허설 (월 1회 필수)

> 백업이 있다는 것과 복구가 된다는 것은 다르다. **복구 리허설 기록이 납품 증적이다.**

### 절차
1. 리허설용 임시 디렉터리에 최신 백업 압축 해제
2. `node scripts/deploy/db-verify.mjs <임시경로>/data.db` — integrity_check `ok` 확인
3. 임시 포트로 앱 기동 (`PORT=3999`) → 로그인 → 자산 총계가 백업 시점 감사로그와 일치하는지 확인
4. 임시 기동 종료, 임시 디렉터리 삭제
5. 아래 양식 기재 후 운영 파일철에 보관

## 5. 운영 환경 변수 (전체)

| 변수 | 기본 | 설명 |
|---|---|---|
| `AUTH_SECRET` | (없음) | **운영 필수** — 미설정/기본값이면 production 기동 거부 |
| `SESSION_TTL_HOURS` | 24 | 세션 수명. 짧게(예: 4) 두면 만료 배너+연장 버튼과 조합해 유휴 타임아웃으로 동작 |
| `COOKIE_SECURE` | false | TLS 적용 시 true (deploy-tls.md) |
| `RETENTION_DAYS` | 365 | 로그 보존일수 — asset-retention.timer가 초과분 프루닝. **기관 보존정책 확정 후 조정** |
| `TRUST_PROXY` | false | 리버스 프록시 뒤 배포 시 true (로그인 rate-limit IP 식별) |
| `SMOKE_MIN_ASSETS` 등 | 100 | smoke 가드레일 하한 — 기관 규모에 맞게 |

## 6. 성능 기준선 (하자검수 참고치)

| 항목 | 기준선 (자산 866 · 부속 442 실측) | 파단점 |
|---|---|---|
| 자산 목록 API | < 200ms (전량) | 자산 1만대 초과 시 `?limit=` 페이지네이션 경로로 전환 (API 지원 완료, UI 전환은 유지보수 항목) |
| 엑셀 임포트 | 수백 행 < 1초 (결과 화면에 소요시간 표시) | 5,000행 이상 분할 업로드 권장 |
| 감사로그 조회 | 50건/페이지 인덱스 스캔 (TEMP B-TREE 없음) | 연 10만 행 규모까지 검증된 인덱스 구성 |
| 백업 | data.db 크기 비례 (수십 MB → 수 초) | — |
