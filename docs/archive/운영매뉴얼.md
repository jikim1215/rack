# 정보시스템 자산관리 (asset-inventory) 운영 매뉴얼

> ⚠️ 이 문서는 **`docs/관리자매뉴얼.md`**(현재 운영환경 반영 정본)로 대체되었습니다. 최신 내용·안전 절차는 그쪽을 보세요.

폐쇄망 Rocky Linux 8.10 단일 서버 운영/긴급대응용. **명령어를 그대로 복사·붙여넣기** 하면 됩니다.
대부분 `root`(또는 `sudo`) 권한이 필요합니다. 설치는 `docs/README-설치.md` 참고.

> 🔴 긴급할 때는 **[8. 긴급 대응](#8-긴급-대응)** 으로 바로 가세요.

---

## 1. 시스템 개요

```
[사용자 PC]  ── HTTPS 443 ──▶  [nginx]  /etc/nginx/conf.d/itam.conf  (TLS 종단 + 프록시)
                                    │ HTTP 127.0.0.1:3100
                                    ▼
                              [asset-inventory] systemd (Next standalone, 사용자=asset)
                                    │
                                    ▼
                              [SQLite DB] /opt/asset-inventory/data.db
```

### 핵심 경로 / 포트 / 계정

| 항목 | 값 |
|------|----|
| 앱 디렉터리 | `/opt/asset-inventory` |
| 환경설정 | `/opt/asset-inventory/.env` (권한 600, owner=asset) |
| DB 파일 | `/opt/asset-inventory/data.db` (+ `-wal`, `-shm`) |
| 백업 | `/opt/asset-inventory/backups/` |
| systemd 유닛 | `/etc/systemd/system/asset-inventory.service` |
| 앱 포트 | `127.0.0.1:3100` (외부 비노출 — share 3000 과 공존) |
| nginx 설정 | `/etc/nginx/conf.d/itam.conf` |
| nginx 포트 | `443`(HTTPS), `80`(→443 리다이렉트). server_name=`itam.example.go.kr`(share 와 SNI 분리) |
| TLS 인증서 | `/etc/ssl/certs/itam.crt`(fullchain), 키 `/etc/ssl/private/itam.key`. 원본 PEM: `/opt/asset-inventory/ssl/` |
| 접속 도메인 | `itam.example.go.kr` (내부 DNS → 서버IP) |
| 서비스 계정 | `asset` (nologin) |
| 관리자 ID | `admin@example.go.kr` (이메일 기반 로그인 ID, 초기 비번 `admin123`, 첫 로그인 후 변경 필수) |

## 2. 일상 운영 — 서비스 제어

```bash
# 상태
systemctl status asset-inventory nginx

# 재시작 (.env·설정 변경 후)
sudo systemctl restart asset-inventory      # 앱만
sudo systemctl restart nginx                # nginx만

# 부팅 자동시작(이미 설정됨)
sudo systemctl enable asset-inventory nginx
```

### 헬스체크 (정상 = 200/302/307)

```bash
curl -s  -o /dev/null -w "app  : %{http_code}\n" http://127.0.0.1:3100/login                      # 내부 앱
curl -sk --resolve itam.example.go.kr:443:127.0.0.1 -o /dev/null -w "https: %{http_code}\n" https://itam.example.go.kr/login   # 프록시(SNI 필수)
ss -tlnp | grep -E ':3100|:443|:80'                                                               # 리슨 포트
```

## 3. 로그 확인

```bash
journalctl -u asset-inventory -f                       # 앱 실시간
```

## 4. 설정 변경

### 4.1 `.env` 변경
```bash
sudo vi /opt/asset-inventory/.env
sudo chown asset:asset /opt/asset-inventory/.env && sudo chmod 600 /opt/asset-inventory/.env
sudo systemctl restart asset-inventory
```
> `.env` 는 단순 `KEY=VALUE`. 셸 문법 금지. 값에 공백/특수문자가 있어도 따옴표 없이 그대로.

### 4.2 서버 IP 변경 / nginx 재구성
```bash
sudo bash /opt/asset-inventory/scripts/deploy/setup-nginx.sh nginx   # IP 자동감지 → conf·인증서 재적용
```

### 4.3 정식 SSL 인증서 갱신 (★ 반기마다 필수)

본 인증서(`*.example.go.kr`)는 유효기간이 약 6개월이라 **반기마다 갱신**해야 합니다. 폐쇄망이라 자동갱신 불가 → 캘린더 리마인더로 고정하고 **만료 2~4주 전** 교체하세요.

```bash
# 0) (반입 후) 새 인증서 사전 검증
openssl x509 -in /path/cert.pem -noout -subject -enddate                       # 도메인·새 만료일
openssl verify -untrusted /path/DigiCertCA.pem /path/cert.pem                   # 'OK' 기대
[ "$(openssl x509 -in /path/cert.pem -noout -pubkey)" = "$(openssl pkey -in /path/newkey.pem -pubout)" ] \
  && echo "key match OK" || echo "키-인증서 불일치!"

# 1) PEM 3종 교체
sudo cp /path/cert.pem /path/DigiCertCA.pem /path/newkey.pem /opt/asset-inventory/ssl/

# 2) nginx 재구성 (인증서 자동 판별 → fullchain 재구성)
sudo bash /opt/asset-inventory/scripts/deploy/setup-nginx.sh nginx

# 3) 적용 확인 — 새 만료일 + 로그인 200
echo | openssl s_client -connect 127.0.0.1:443 -servername itam.example.go.kr 2>/dev/null | openssl x509 -noout -enddate
curl -sk -o /dev/null -w '%{http_code}\n' https://itam.example.go.kr/login
```
> 개인키가 암호보호(`ENCRYPTED`)면 `openssl rsa -in newkey.pem -out newkey.pem` 로 평문화 후 넣기.
> `ssl/` 를 비우면 자체서명으로 폴백되어 브라우저 경고 발생 — 정식 운영 중 비우지 말 것.

### 4.4 접속 도메인(`itam.example.go.kr`) DNS
폐쇄망이라 공인 DNS가 안 통합니다. **기관 내부 DNS에 `itam.example.go.kr → 서버IP` A레코드**를 등록해야 도메인 접속이 됩니다. share 와 같은 서버로 공존하므로 nginx 는 `server_name itam.example.go.kr` 로 SNI 분리 — **IP 직접 접속은 itam 이 아니라 default(share)로 갑니다.** 임시 확인은 클라이언트 `hosts` 에 `서버IP itam.example.go.kr` 추가.

## 5. 계정 관리

### 5.1 관리자 비밀번호 재설정 / 계정 잠금 해제 (비상시)

> 🚫 **`scripts/db-seed.mjs` 를 재설정 용도로 실행하지 마세요 — 시작 시 모든 테이블을 DROP 하여 운영 DB 전체가 삭제됩니다(`--reset-admin` 옵션 없음).**
> 안전한 재설정/잠금해제 절차는 **`docs/관리자매뉴얼.md §5.2`** 를 따르세요. 표준은 로그인 후 **설정 > 사용자 관리**(다른 admin 계정으로 초기화)입니다.

### 5.2 사용자/권한
로그인(admin) → **설정 > 사용자 관리**(계정 생성/이메일(ID) 변경/비활성/삭제/**비밀번호 초기화**) · **설정 > 권한 관리**(메뉴별 접근/쓰기/승인). 로그인 ID는 이메일 기반(공존시스템 규약, SSO 없음). **비밀번호 초기화 = 비밀번호를 사용자 이메일로 설정 + 강제변경**(전달할 비밀 없음 — 사용자는 이메일로 로그인 후 새 비밀번호 설정). 기본 계정(`admin@example.go.kr` 등)도 개명·삭제 가능하나 마지막 활성 admin·본인 계정은 삭제/강등이 차단된다.

## 6. 백업 · 복구

- 자동 백업: `asset-backup.timer` (매일 02:00) → `backups/` 에 gzip, 권한 600, N일 초과 자동 정리
- 자동 보존 프루닝: `asset-retention.timer` (매일 03:30) → 감사로그/접속기록 1년 초과 삭제

```bash
# 수동 백업
sudo bash /opt/asset-inventory/scripts/deploy/backup.sh

# 백업 목록
ls -l /opt/asset-inventory/backups/

# 복구 리허설(무중단 검증)
sudo bash /opt/asset-inventory/scripts/deploy/restore.sh --rehearse /opt/asset-inventory/backups/<파일>.gz

# 실복구 (서비스 중지 → pre-restore 백업 → 복원 → 검증 → 재기동)
sudo bash /opt/asset-inventory/scripts/deploy/restore.sh /opt/asset-inventory/backups/<파일>.gz

# 타이머 상태
systemctl list-timers 'asset-*'
```

## 7. 데이터 이관 (엑셀)

- 자산: 로그인 → **자산관리 > 엑셀 업로드** (또는 이관 스크립트)
- 유지관리 대상/금액: **유지보수 > 유지관리 대상/금액 탭 > 임포트** (xlsx)
- 부속자산: `scripts/import-subassets.mjs`

> DB 경로 일관성: 이관·시드는 반드시 `.env` 의 `ASSET_DB_PATH=/opt/asset-inventory/data.db` 를 가리키게 하세요. 안 그러면 빈 DB를 읽어 로그인이 "사용자 없음"으로 막힙니다.

## 8. 긴급 대응

### 증상: 접속 불가 (브라우저 연결 안 됨)
```bash
systemctl status asset-inventory nginx        # 둘 다 active 인지
ss -tlnp | grep -E ':443|:3100'               # 리슨 확인
sudo systemctl restart nginx asset-inventory
```

### 증상: 502 Bad Gateway
```bash
curl -s -o /dev/null -w '%{http_code}\n' http://127.0.0.1:3100/login   # 앱 살아있나
sudo setsebool -P httpd_can_network_connect 1                          # SELinux 프록시 허용
sudo systemctl restart asset-inventory nginx
```

### 증상: 로그인 "서버 연결 실패" / 500
```bash
grep -c '^AUTH_SECRET=' /opt/asset-inventory/.env    # 1 이어야 함(없으면 세션발급 실패)
journalctl -u asset-inventory -p err -n 50 --no-pager
```
→ `AUTH_SECRET` 누락이면 `.env` 에 강력한 랜덤값 설정 후 `systemctl restart asset-inventory`.

### 증상: 로그인 "사용자가 없습니다"(503)
→ DB 경로 불일치. `.env` 의 `ASSET_DB_PATH` 가 실제 데이터 DB를 가리키는지 확인.

### 증상: 인증서 경고 (브라우저)
→ 자체서명으로 폴백된 상태. §4.3 절차로 정식 인증서 재적용.

### 증상: better-sqlite3 native 로드 오류
```bash
sudo bash /opt/asset-inventory/scripts/deploy/native-planb.sh   # 소스 리빌드(gcc/make/python3 필요)
sudo systemctl restart asset-inventory
```
