# itam 실서버 반입 — 최종 점검 및 절차 (공존시스템 공존)

대상: 폐쇄망에서 `share.example.go.kr`(공존시스템) 운영 중인 서버에 `itam.example.go.kr` 추가.
검증 완료(VMware Rocky 8.10, 2026-07-15): **실서버 순서(공존시스템 nginx 1.30 → itam) 재현, 경고 0, 두 앱 SNI 공존, itam 로그인 E2E 200.**

---

## 0. 반입물 (단일 파일)

`asset-inventory-offline.tar.gz` (약 68MB) — **이 안에 전부 포함**:
- Next standalone 앱 + better-sqlite3 native(glibc 2.28 링크)
- 번들 Node 22.11 (`node-linux-x64.tar.xz`)
- nginx RPM 8종 (독립 서버용 — 공존시스템 서버엔 nginx 이미 있어 미사용)
- 배포 스크립트 (`setup-nginx.sh`, `nginx-itam.conf`) + 문서

> **SSL 인증서는 번들에 없다 — 공존시스템(share)의 인증서를 공유한다.** 실서버에 이미 배치된
> `/etc/ssl/certs/shared.crt`(`*.example.go.kr`, itam 커버)를 `setup-nginx.sh` 가 자동 참조.
> 갱신은 공존시스템 한 곳만 하면 itam 도 자동 반영(nginx reload). **인증서 별도 반입 불필요.**

---

## 1. 반입 전 확인 (담당자)

- [ ] 서버가 **Rocky Linux 8.x, x86_64, glibc 2.28** (실측: `ldd --version`, `uname -m`)
- [ ] 공존시스템(share)가 **정상 운영 중** (`systemctl is-active shared nginx`) — itam 은 이 인증서/nginx 를 공유
- [ ] **포트 3100 이 비어있음** (`ss -tlnp | grep 3100` → 결과 없음). 쓰고 있으면 설치 시 `NEXT_INTERNAL_PORT=3200` 지정.
- [ ] 디스크 여유 (`df -h /opt` — 최소 2GB)
- [ ] 공존시스템 인증서 유효 (`openssl x509 -in /etc/ssl/certs/shared.crt -noout -enddate`). itam 도 이걸 공유하므로 만료 임박이면 공존시스템 쪽 갱신 선행.

---

## 2. 설치 (단일 명령)

```bash
# USB/망연계로 반입한 tar.gz 를 서버로 옮긴 뒤
tar -xzf asset-inventory-offline.tar.gz
sudo bash asset-inventory/scripts/deploy/setup-nginx.sh
#   포트 변경이 필요하면:
#   sudo NEXT_INTERNAL_PORT=3200 bash asset-inventory/scripts/deploy/setup-nginx.sh
```

자동 수행 (공존시스템 무영향):
- `/opt/asset-inventory` 배치 + 번들 Node + `asset` 계정
- **nginx 재설치 안 함** (`command -v nginx` 스킵 → 공존시스템 nginx 1.30 재사용)
- `conf.d/itam.conf` 추가 (server_name=itam.example.go.kr, upstream 3100, **nginx 버전 감지해 http2 구문 자동 선택**)
- **인증서 자체 생성 안 함** — 공존시스템 의 `/etc/ssl/certs/shared.crt`(`*.example.go.kr`) 공유 참조 (없으면 명확히 실패, `SSL_CRT`/`SSL_KEY` 로 경로 지정)
- SELinux 라벨/부울, 방화벽, systemd(3100) 기동
- **빈 DB 자동 초기화** (admin@example.go.kr / admin123, 데모 데이터 없음)

## 3. 내부 DNS (담당자 — 유일한 수동 인프라 작업)

내부 DNS 에 A레코드 추가 (share 와 동일 IP):
```
itam.example.go.kr  →  <서버 IP>
```
> **IP 직접 접속은 itam 이 아니라 default(share)로 간다.** 반드시 도메인으로 안내.

---

## 4. 설치 후 검증

```bash
IP=<서버IP>
systemctl is-active shared asset-inventory nginx     # 셋 다 active
ss -tlnp | grep -E ':3000|:3100|:443'                  # share=3000, itam=3100, nginx=443
sudo nginx -t                                          # 경고/에러 0 (deprecated 경고 없어야 정상)

# SNI 로 도메인별 앱 확인
curl -sk --resolve itam.example.go.kr:443:$IP  https://itam.example.go.kr/login  | grep -oiE '<title>[^<]*</title>'   # 정보시스템 자산관리
curl -sk --resolve share.example.go.kr:443:$IP https://share.example.go.kr/login | grep -oiE '<title>[^<]*</title>'   # K-Flow

# itam 로그인 (200)
curl -sk --resolve itam.example.go.kr:443:$IP -o /dev/null -w '%{http_code}\n' https://itam.example.go.kr/login
```
브라우저: `https://itam.example.go.kr` → admin@example.go.kr / admin123 → **첫 로그인 후 비번 변경** → 사용자/권한 설정 → 엑셀로 실데이터 투입.

---

## 5. 인증서 (공존시스템 공유 — itam 별도 갱신 불필요)

- itam 은 자체 인증서를 만들지 않고 **공존시스템 의 `/etc/ssl/certs/shared.crt`(`*.example.go.kr`)를 공유**한다.
- **갱신은 공존시스템 한 곳에서만** (`sudo bash /opt/shared/install.sh nginx`). itam 은 별도 갱신 불필요 —
  공존시스템 가 인증서를 교체하면 같은 파일을 참조하는 itam 도 자동 최신(itam 은 `nginx reload` 만 하면 반영, 보통 공존시스템 재구성이 nginx 를 리로드하므로 자동).
- itam 인증서 경로가 다르면 설치/재구성 시 지정:
  ```bash
  sudo SSL_CRT=/etc/ssl/certs/foo.crt SSL_KEY=/etc/ssl/private/foo.key \
       bash /opt/asset-inventory/scripts/deploy/setup-nginx.sh nginx
  ```
- 현재 인증서 만료: `Sep 25 2026` (반기 갱신 대상 — 공존시스템 캘린더에 포함).

---

## 6. 롤백 (문제 시 itam 만 제거, share 무영향)

```bash
sudo systemctl disable --now asset-inventory
sudo rm -f /etc/nginx/conf.d/itam.conf
sudo nginx -t && sudo systemctl reload nginx     # share 그대로, itam 만 사라짐
# 완전 제거: sudo rm -rf /opt/asset-inventory /var/lib/asset-inventory
#            (인증서는 공존시스템 공유 — itam 이 만든 파일 없음. `shared.crt/key` 는 공존시스템 것이므로 절대 삭제 금지)
```

## 리허설에서 검증·해결된 이슈 (실서버 재발 방지 — 모두 코드 반영)

| # | 이슈 | 해결 |
|---|------|------|
| 1 | node-gyp(python 3.6) | 빌드머신 python3.11 (실서버 무관) |
| 2 | c++20(gcc 8.5) | 빌드머신 gcc-toolset-12 (실서버 무관) |
| 3 | nginx 의존 RPM 누락 | rpms/*.rpm 전체 설치 |
| 4 | SELinux user_home_t → .env 로드 실패 | restorecon -R |
| 5 | nginx default_server / http2 | server_name 명시 + **버전 감지 http2** |
| 6 | 프록시 뒤 localhost:3000 리다이렉트 | X-Forwarded-Host 절대 URL |
| 7 | 빈 DB "사용자 없음" | SEED_MINIMAL 자동 초기화 |
| 8 | nginx 1.30 `listen...http2` deprecated 경고 | 버전 감지(1.25.1+ → `http2 on;`) |

> 이슈 8 은 실서버 순서(공존시스템 가 nginx 1.30 을 먼저 설치) 재현에서만 나타난 것 — 실서버 조건 그대로 검증·해결했다.
