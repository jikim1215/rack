# 변경 이력 — 정보시스템 자산관리 (itam)

버전은 `package.json` 의 `version` 하나가 정본이다(SemVer `주.부.수`).

| 올리는 자리 | 언제 |
|---|---|
| 주(major) | 되돌리기가 DB 복원 없이는 안 되는 변경 — 구판 앱이 새 스키마를 못 읽거나 데이터 형식이 바뀜 |
| 부(minor) | 기능·화면 추가나 변경, 운영 절차(배포·점검 스크립트) 변경 |
| 수(patch) | 기능 변화 없는 결함 수정 |

**확인하는 곳** — 로그인 후 사이드바 맨 아래(버전 · 커밋, 마우스를 올리면 빌드 시각), 서버 안에서 앱 포트로 부른 `/api/health` 의 `version`·`commit`·`builtAt`(nginx 경유 외부 요청은 `{"ok":true}` 만), 번들 최상위 `VERSION` 파일, 반입 안내 `배포방법.txt` 첫 줄, 업그레이드·롤백 출력(`현재 → 새`).
커밋 뒤에 `-dirty` 가 붙어 있으면 커밋되지 않은 변경이 섞인 빌드다 — 정식 반입본이 아니다.

**릴리스 절차** — `npm version <x.y.z> --no-git-tag-version` → 이 파일에 항목 추가 → 커밋 → `git tag -a v<x.y.z>` → `git push origin main v<x.y.z>` → GitHub Actions(Release)가 Rocky 8.10 에서 번들을 빌드해 Releases 에 올린다(이 파일의 해당 항목이 릴리스 노트). 상세는 `docs/DEPLOY.md` §2.

## v1.2.2 — 2026-10-12

기능 변화 없음. 번들을 GitHub Release 로 내기 시작한 판.

- `v<x.y.z>` 태그를 push 하면 GitHub Actions 가 Rocky Linux 8.10(glibc 2.28)에서 타입검사·테스트 후 오프라인 번들을 빌드·점검해 Releases 에 세 파일(`asset-inventory-offline.tar.gz` · `SHA256SUMS.txt` · `배포방법.txt`)을 올린다. `main` push·PR 마다 CI(타입검사·테스트·빌드) 실행
- `build-release.sh` 가 시작 직후 아무 출력 없이 종료(exit 141)하던 간헐적 결함 수정 — glibc 버전을 `ldd --version | head -1` 로 읽다가 SIGPIPE 로 죽었다. `getconf GNU_LIBC_VERSION` 으로 읽는다

## v1.2.1 — 2026-10-12

보안 점검 지적(미인증 내부 정보 노출, OWASP A05) 수정판.

- 외부(nginx 경유) `/api/health` 는 `{"ok":true}` 와 200/503 만 낸다 — 버전·커밋·빌드 시각·DB 스키마·가동 시간·응답 지연은 서버 안에서 앱 포트(`127.0.0.1:<PORT>`)로 직접 부른 경우에만(배포·업그레이드·롤백 스크립트는 그대로 동작)
- 로그인 전 화면의 버전 표기 제거. 무인증으로 받는 공통 JS 청크(`/_next/static/.../layout-*.js`)에 커밋·빌드 시각이 박혀 있던 것도 제거 — 사이드바 버전은 로그인 후 `/api/auth/me` 로 받는다
- 로그인: 없는 계정도 비밀번호 해시 비교(scrypt)를 거친다 — 메시지는 같아도 응답 시간 차이로 계정 존재 여부가 드러나던 사용자 열거 차단
- nginx 재구성(`setup-nginx.sh nginx`)이 `server_name` 을 기본값(`itam.example.go.kr`)으로 되돌리던 결함 수정 — `.env` 의 `PUBLIC_FQDN` 을 따른다

## v1.2.0 — 2026-10-07

관리부서명을 `teams.team_name` 한 곳에서만 읽는다 — 조직 개편으로 부서명을 바꾸면(설정 → 팀 이름 변경) 소속 자산 전체에 즉시 반영된다.

- 대시보드 "최근 등록 자산"의 부서, 제출용 관리대장의 "부서명", 자산 내보내기의 "관리부서"가 늘 빈 칸이던 결함 수정 — 남아 있던 레거시 `assets.department`(앱이 쓰지 않는 컨럼, 운영 DB 전부 빈 값)를 읽고 있었다. 이제 소유 팀명을 보여주고, 내보낸 파일을 다시 올리면 관리부서가 그대로 유지된다(예전엔 빈 칸이라 미배정으로 들어갔다)
- `assets.department` 컨럼 제거(기동 시 자동). 자산 수정 화면의 "부서 (읽기전용·레거시)" 칸 제거
- 미배정 큐의 "부서별 일괄 배정" 패널 제거 — 위 컨럼을 묶음 기준으로 썼어 항상 "(부서 없음)" 한 묶음만 나왔다. 목록 선택 재배정(페이지를 넘겨도 선택 유지)은 그대로
- 되돌리기: v1.1.1 앱은 기동 시 빈 `department` 컨럼을 다시 만들므로 DB 복원(`--with-db`) 없이 돌아갈 수 있다

## v1.1.0 — 2026-10-02

버전 표기를 도입한 첫 판. 이전 판은 모두 `/api/health` 가 `1.0.0` 으로 보고했다 — 아래는 그 판들과 비교한 변경이다.

### 버전 관리
- 화면(로그인 · 사이드바), `/api/health`, 번들 `VERSION` 파일, 배포·업그레이드·롤백 출력에 버전·커밋·빌드 시각 표시

### 데이터 보호
- ★ 구판은 서버를 재시작할 때마다 자산의 소유 팀 · 랙 L/R · 현행 확인 도장 · 일괄등록 배치 값을 비웠다 — 더 이상 지우지 않고, 업그레이드가 감사로그에서 빈 값만 되살린다
- 엑셀 일괄등록 · 배치 되돌리기 500 오류 수정(구버전 DB 의 `import_batch_id` 누락 자동 보강)
- `db-seed.mjs` 가 사용자 있는 DB 를 거부(운영 DB 전체 삭제 사고 방지)

### 보안
- 팀 간 격리 우회 차단 — 다른 팀 전용 위치에 랙·IP 대역·배선반 만들기, 다른 팀 자산을 부속의 상위로 연결하기
- 감사로그 누락 보강(위치 · 계약 · 업체 · IP 대역 · 포트 연결 · 반출입 · 확장 필드 · 메일 설정 · 비밀번호 변경)
- 엑셀 업로드: 압축 폭탄(작은 파일이 수백 MB 로 풀리는 zip) · 위장 파일 차단, `.xlsx` 만 허용
- CSV 내보내기 수식 주입 방지(`=`·`+`·`-`·`@` 로 시작하는 셀)
- 클라이언트 IP 위조 차단(허용 IP · 로그인 잠금 · 접속기록)
- Next.js 15.5.27 · nodemailer 10 · postcss 8.5.28 — 알려진 취약점 0건(`npm audit`)

### 웹 접근성 (KWCAG 2.2)
- 모든 입력칸 레이블, 화면별 탭 제목, 키보드로 카드·칸 열기, 본문 바로가기
- 대화상자 초점 가두기 · Esc 닫기 · 닫은 뒤 원래 자리로 복귀
- 글자 명도 대비 4.5:1 이상(어두운 배경 위 안내 문구 포함)

### 대량 데이터 (자산 1만 건 기준)
- 미배정 큐 50건씩 페이지 나눔 — 첫 화면 8.3MB → 117KB
- 대시보드 랙 위치 충돌 계산 4.4초 → 0.13초, IP 대역 화면 16.3초 → 0.36초
